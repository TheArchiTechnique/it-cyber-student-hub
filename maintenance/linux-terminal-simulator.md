## Shared engine and filesystem

All modules are in `docs/assets/javascripts/linux-terminal/`:

- `filesystem.mjs` owns the only virtual filesystem. It resolves case-sensitive absolute/relative paths component by component, checks ancestor search permission, maintains ownership/modes/timestamps, and provides shared read/write/list/creation plus copy/move/remove/chmod/chown operations. Directory read permission lists names; search permission permits accessing children. Long listings check access to each child's metadata. New copies belong to the effective user, use source permissions subject to the fixed 022 creation policy, and have independent nodes. Existing file copies retain destination ownership/mode. Moves preserve subtrees and metadata, update current/previous directory paths, and need parent permissions rather than source-file write permission.
- `parser.mjs` retains Phase 1 quoting, escaping, home/environment expansion, comments, and redirection protections. It never evaluates student text. Shell pipes, wildcard expansion, chains, substitutions, and interactive standard input remain unsupported. Quote find patterns so the shell passes them to find.
- `file-commands.mjs` registers handlers in the existing shell dispatcher. It is not another shell or filesystem. It implements transfer operands, limited text search, bounded wildcard matching, permission modes, and root/student/numeric identity parsing.
- `shell.mjs` dispatches all commands against its existing VFS and returns stdout/stderr/status plus optional manual/editor actions. Nano's action contains a buffer referencing this VFS. Interactive Nano/clear output redirection is rejected before opening a destination file. Other output redirection preserves Phase 1 shell open/truncate-before-dispatch behavior.
- `manuals.mjs` documents only implemented syntax. `--help` returns the same concise help inline for supported commands other than echo.
- `nano.mjs` provides `NanoSession` and the view mounted inside the original terminal. The buffer uses the shell's VFS; opening a new name creates no filesystem node. Saving uses the same permission/size checks as shell redirection. A native multiline text area supplies ordinary editing, cursor navigation, selection, undo, and copy/paste, styled as a Nano terminal buffer. Ctrl+O prompts for the filename; Enter writes; Ctrl+X handles Save/Discard/Cancel; Ctrl+G opens concise help. Touch controls offer the same operations. Failed saves retain the buffer and filename prompt. New nonempty text receives Nano's normal final newline. Unsaved edits trigger the browser's unload warning; unsaved buffers themselves are not restored after navigation. Reset is disabled while an editor is active. This is one buffer, not full GNU Nano emulation.
- `terminal.mjs` preserves the original transcript, command recall, completion, dialogs, theme controls, safe text rendering, and storage notices, and switches visibility between that terminal and Nano. Nano saves invoke the same workstation persistence function.

## Supported file operations and permissions

- `cp [-r] SOURCE ... DESTINATION`: independent file copies, recursive directory copies, existing-directory merge rules, and multiple-source targets. Self-copy and copying a directory into a descendant are refused. Unsupported preservation/interactive options are not claimed.
- `mv SOURCE ... DESTINATION`: file rename/overwrite, directory-tree moves, and multiple sources into an existing directory. A conflicting directory must be empty. Parent-to-descendant moves and replacing an active working directory are refused.
- `rm [-rf] PATH ...`: file deletion, recursive removal, missing-path suppression with `-f`, and sticky-directory ownership restrictions. Force never bypasses permissions. There are no simulated write-protection prompts. Each recursive operand is preflighted before deletion, so permission failure leaves that subtree intact; separate successful operands still apply. This differs from GNU rm's possible partial traversal effects and is stated in the short manual. Workstation foundation directories and the current directory/ancestors have explicit **simulator safety** restrictions. Removing an old working directory clears its stale previous-directory reference.
- `chmod MODE FILE ...`: three/four-digit octal modes and explicit `u/g/o/a` symbolic `+/-/=` operations with `rwx`, including comma-separated clauses. Owner/root authorization and parent traversal apply. Mode changes affect subsequent reads, writes, listing, traversal, copies, and removal. File execute/set-ID bits are represented; executing binaries/scripts is not implemented. No recursive chmod or ACLs are supported.
- `chown USER[:GROUP] FILE ...`: root/student names and numeric IDs. A different owning user requires root. An owner can retain their own ID and select one of their groups, matching ordinary authorization rules. Set-ID bits clear when identity changes. Successful elevated changes are tested through controlled engine fixtures only; no student-facing sudo/su bypass exists.
- `grep [-in] PATTERN FILE ...`: searches saved text, with case folding, line numbers, multi-file prefixes, and exit status 0/1/2 for match/no match/error. This subset accepts plain text; regular-expression metacharacters are explicitly rejected. No JavaScript regular expressions run from student patterns. Sample application/authentication logs accompany the original support log.
- `find [PATH ...] [-name PATTERN] [-type f|d]`: recursive permission-aware traversal, filename `*`/`?` matching, and AND combination of these two predicates. Root entries and hidden entries participate. No matches is successful; traversal failure is nonzero and preserves accessible results. Unsupported predicates, escapes, and bracket classes are rejected.

## Persistence and migration

The workstation still uses `student-hub:linux-terminal:v1`; retaining the key lets existing students load their work. The serialized schema is now version 2. Version 1 migration preserves the entire validated filesystem, file contents, metadata, current/previous directories, history, and session status, and adds the two new log samples only when absent and within the entry limit. The migration does not overwrite an existing file. Version 2 does not re-create intentionally removed logs.

Working directories are validated for directory existence during restore, not current access permission. This preserves a valid session after `chmod` removes search access from its active directory. Each later command still checks permissions. Current paths are remapped by moves, and deletion safeguards prevent dangling active references. Root test-fixture sessions are deliberately not a persistent student login; Phase 3 must extend identity/session validation before implementing administration.

The original bounds remain: 8192 input characters, resolved paths shorter than 8192 characters, one million text characters per file, 5000 filesystem entries, 200 recalled commands, and an eight-million-character serialized checkpoint limit. Oversized saves never replace the previous checkpoint. The visible transcript retains 120 entries and limits each displayed output to 50,000 characters with a notice. Long listings show UTF-8 file bytes, zero modeled directory size, and UTC modification time. Storage failure leaves the in-memory workstation usable with an explicit warning. Reset confirms replacement of the workstation key and leaves unrelated progress and theme preferences intact.
