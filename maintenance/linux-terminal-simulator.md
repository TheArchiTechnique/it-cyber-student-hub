## Shared engine and filesystem

All modules are in `docs/assets/javascripts/linux-terminal/`:

- `filesystem.mjs` owns the only virtual filesystem. It resolves case-sensitive absolute/relative paths component by component, checks ancestor search permission, maintains ownership/modes/timestamps, and provides shared read/write/list/creation plus copy/move/remove/chmod/chown operations. Directory read permission lists names; search permission permits accessing children. Long listings check access to each child's metadata. New copies belong to the effective user, use source permissions subject to the fixed 022 creation policy, and have independent nodes. Existing file copies retain destination ownership/mode. Moves preserve subtrees and metadata, update current/previous directory paths, and need parent permissions rather than source-file write permission.
- `parser.mjs` retains Phase 1 quoting, escaping, home/environment expansion, comments, and redirection protections. It never evaluates student text. Shell pipes, wildcard expansion, chains, substitutions, and interactive standard input remain unsupported. Quote find patterns so the shell passes them to find.
- `file-commands.mjs` registers handlers in the existing shell dispatcher. It is not another shell or filesystem. It implements transfer operands, limited text search, bounded wildcard matching, permission modes, and root/student/numeric identity parsing.
- `shell.mjs` dispatches all commands against its existing VFS and returns stdout/stderr/status plus optional manual/editor actions. Nano's action contains a buffer referencing this VFS. Interactive Nano/clear output redirection is rejected before opening a destination file. Other output redirection preserves Phase 1 shell open/truncate-before-dispatch behavior.
- `manuals.mjs` documents only implemented syntax. `--help` returns the same concise help inline for supported commands other than echo.
- `nano.mjs` provides `NanoSession` and the view mounted inside the original terminal. The buffer uses the shell's VFS; opening a new name creates no filesystem node. Saving uses the same permission/size checks as shell redirection. A native multiline text area supplies ordinary editing, cursor navigation, selection, undo, and copy/paste, styled as a Nano terminal buffer. Ctrl+O prompts for the filename; Enter writes; Ctrl+X handles Save/Discard/Cancel; Ctrl+G opens concise help. Touch controls offer the same operations. Failed saves retain the buffer and filename prompt. New nonempty text receives Nano's normal final newline. Unsaved edits trigger the browser's unload warning; unsaved buffers themselves are not restored after navigation. Reset is disabled while an editor is active. This is one buffer, not full GNU Nano emulation.
- `terminal.mjs` preserves the original transcript, command recall, completion, dialogs, theme controls, safe text rendering, and storage notices, and switches visibility between that terminal and Nano. Nano saves invoke the same workstation persistence function.

## Supported file operations and permissions

- `cp [-r] SOURCE ... DESTINATION`: independent file copies, recursive directory copies, existing-directory merge rules, and multiple-source targets. Self-copy and copying a directory into a descendant are refused. Unsupported preservation/interactive options are not claimed.
- `mv SOURCE ... DESTINATION`: file rename/overwrite, directory-tree moves, and multiple sources into an existing directory. A conflicting directory must be empty. Parent-to-descendant moves and replacing an active working directory are refused.
- `rm [-rf] PATH ...`: file deletion, recursive removal, missing-path suppression with `-f`, and sticky-directory ownership restrictions. Force never bypasses permissions. There are no simulated write-protection prompts. Each recursive operand is preflighted before deletion, so permission failure leaves that subtree intact; separate successful operands still apply. This differs from GNU rm's possible partial traversal effects and is stated in the short manual. Workstation foundation directories and the current directory/ancestors have explicit **simulator safety** restrictions. Removing an old working directory clears its stale previous-directory reference.
- `chmod MODE FILE ...`: three/four-digit octal modes and explicit `u/g/o/a` symbolic `+/-/=` operations with `rwx`, including comma-separated clauses. Owner/root authorization and parent traversal apply. Mode changes affect subsequent reads, writes, listing, traversal, copies, and removal. File execute/set-ID bits are represented; executing binaries/scripts is not implemented. No recursive chmod or ACLs are supported.
- `chown USER[:GROUP] FILE ...`: root/student names and numeric IDs. A different owning user requires root. An owner can retain their own ID and select one of their groups, matching ordinary authorization rules. Set-ID bits clear when identity changes. Student-facing elevation now uses the fictional sudo policy. Authorization is shared with every other VFS operation.
- `grep [-in] PATTERN FILE ...`: searches saved text, with case folding, line numbers, multi-file prefixes, and exit status 0/1/2 for match/no match/error. This subset accepts plain text; regular-expression metacharacters are explicitly rejected. No JavaScript regular expressions run from student patterns. Sample application/authentication logs accompany the original support log.
- `find [PATH ...] [-name PATTERN] [-type f|d]`: recursive permission-aware traversal, filename `*`/`?` matching, and AND combination of these two predicates. Root entries and hidden entries participate. No matches is successful; traversal failure is nonzero and preserves accessible results. Unsupported predicates, escapes, and bracket classes are rejected.

## Persistence and migration

The workstation still uses `student-hub:linux-terminal:v1`; retaining the key lets existing students load their work. The serialized schema is now version 3. Version 1 migration preserves the entire validated filesystem, file contents, metadata, current/previous directories, history, and session status, and adds the two new log samples only when absent and within the entry limit. The migration does not overwrite an existing file. Version 2 does not re-create intentionally removed logs. Both older versions migrate to version 3 without replacing their validated files, ownership, permissions, paths, or history. The migration adds the designated mount-point directory only if missing and within the entry limit, then supplies the new process/session/volume metadata. It never overwrites an existing mount-point entry. Existing two-record process seeds expand into the defined workstation process table.

Working directories are validated for directory existence during restore, not current access permission. This preserves a valid session after `chmod` removes search access from its active directory. Each later command still checks permissions. Current paths are remapped by moves, and deletion safeguards prevent dangling active references. Version 3 also validates account identities, nested shell contexts and their process IDs, process fields and aggregate CPU/memory bounds, fixed machine metadata, known volumes, detached filesystem trees, and mounted-volume coverage metadata. Root shells and suspended student sessions survive refresh. Temporary sudo/editor authority belongs to VFS instances, never to serialized state. After an elevated Nano save or refresh, the surrounding student shell retains its normal identity.

The original bounds remain: 8192 input characters, resolved paths shorter than 8192 characters, one million text characters per file, 5000 active filesystem entries (detached volume nodes are also counted when creating entries), 200 recalled commands, and an eight-million-character serialized checkpoint limit. Oversized saves never replace the previous checkpoint. The visible transcript retains 120 entries and limits each displayed output to 50,000 characters with a notice. Long listings show UTF-8 file bytes, zero modeled directory size, and UTC modification time. Storage failure leaves the in-memory workstation usable with an explicit warning. Reset confirms replacement of the workstation key and leaves unrelated progress and theme preferences intact.

## Administration, processes and storage

- `system-state.mjs` defines the two account identities, fictional password-free sudo authorization, locked direct-root policy, process records, machine snapshot and volume accounting helpers. These objects are simulator state, never browser/host measurements.
- `system-commands.mjs` extends the existing registry. `sudo` scopes an effective VFS actor with `try/finally`, including errors and nested calls; it never permanently replaces the session user. A captured VFS actor lets `sudo nano` read/save as root throughout the buffer lifetime. Closing the editor revokes that buffer's authority and prevents later saves. Shell redirection is opened before sudo dispatch by the original shell, matching `sudo echo text > /etc/hosts` denial. Interactive command redirection is rejected before truncating a target, including commands wrapped in sudo.
- `sudo -l` describes the training authorization. Student is authorized, root is already privileged, and an unauthorized account/policy is denied. No password entry or actual OS credentials exist. `su` accepts only root/student and an optional leading `-` or `-l`. Ordinary root login fails; `sudo su -` creates a login shell in `/root`. Nested shells retain the previous user, current/previous directory, and shell PID. `exit` restores that context and removes the child process. The original student shell remains open. Nesting is bounded to 16. Foundation, mount, and suspended-working-directory protections keep saved sessions restorable.
- `ps`, `ps -e`, `ps -ef`, and `ps aux` derive from the same process table as `top`. The initial image includes systemd, NetworkManager, Cinnamon, and student Bash. There is no SSH-service claim. Account switches add stable child Bash PIDs; exits remove them and future shells receive new IDs. Snapshots omit transient command processes. `top` uses the existing accessible terminal viewer, exits with q/Escape/Ctrl+C or the return button, and supports `top -b -n 1` inline/redirection. Its uptime is fixed at 2:01, memory at 4 GiB, and CPU/memory/task totals derive from modeled records. No timed updates or host metrics are claimed.
- `du [-hs]` recursively accounts for actual UTF-8 file text rounded up to a 1-KiB block per file; empty files and directories consume zero modeled data blocks. Default output uses 1-KiB units, `-h` formats units, and `-s` suppresses descendant lines. Traversal requires directory read/search permission; metadata size does not require reading file content. Denied subtrees report errors while retaining accessible partial totals.
- `df [-h] [PATH ...]` selects mounted volumes or the filesystem containing each path. Root `/dev/sda1` is 32 GiB with a fixed 4-GiB system-image allocation. Secondary `/dev/sdb1` is 1 GiB with 1 MiB fixed metadata allocation. Used equals fixed allocation plus the same modeled file blocks as du; available equals capacity minus used, with no reserved blocks. Percentage rounds up. Writes/copies and cross-volume moves check capacity. Human-readable totals are rounded display values; exact default 1-KiB columns balance.
- `mount` lists current mounts for any account. Root may mount the known secondary ext4 volume only at an existing, empty, unused `/mnt/training-disk`. That designated-point/empty-directory restriction bounds the simulator; arbitrary devices, alternate paths, options, and filesystem types are rejected. The volume starts with README.txt and a student-writable Reports directory. On mount, its nodes join the single VFS namespace. On unmount, they return to the volume's detached node map; the original empty mount-point metadata returns. There is no second shell/filesystem engine. `df` excludes detached volumes while `fsck -n` can inspect them.
- `umount DEVICE|DIRECTORY` requires root. The current directory of any active or suspended shell makes a volume busy. Mounted points/ancestors cannot be moved or removed; root cannot be unmounted. Stale previous-directory references into a detached volume are cleared. Both mounted and detached contents, ownership, modes, and mount/session/process state survive browser refresh. Reset restores student identity, original process records, and an unmounted clean training volume.
- `fsck -n DEVICE` is explicitly read-only and limited to the known, unmounted ext4 model. It reports recognized volume identity, modeled directory/parent consistency, file/directory counts, and allocated data blocks. Mounted volumes are refused in this simulator, including root; actual filesystem-specific checker behavior may differ. Repairs and actual ext4 internals are not simulated. Unknown devices and repair requests fail; there is no fake successful repair.
