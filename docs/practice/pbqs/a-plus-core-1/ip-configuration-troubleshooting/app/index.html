IPv4 addresses and conflicts
Each host on the same network needs a unique IPv4 address. If two PCs show the same address, do not ignore that evidence because it appears too obvious. Duplicate addresses can cause intermittent or failed connectivity.
Give one PC an available address from its LAN or use DHCP. A wrong static address can also put a PC on a different network entirely.


Subnet mask
The subnet mask determines which portion of an IPv4 address identifies the local network. With 192.168.10.24 and 255.255.255.0, addresses in 192.168.10.x are local host candidates.
A wrong mask changes what the PC considers local versus remote. For example, 255.255.0.0 makes 192.168.110.20 appear local to that PC, even when the service actually needs the router.


Default gateway
The default gateway is the router used to reach destinations outside the local network. A valid-looking IP address can still fail to reach remote services if the gateway is wrong.
Compare the gateway with the actual router and functioning PC. Local communication may still work when the default gateway is incorrect.


DHCP and static settings
DHCP commonly supplies the IPv4 address, subnet mask, default gateway, and DNS information automatically. Static addressing means these settings are configured manually.
Incorrect static settings can create address conflicts or place a PC on the wrong network. DHCP must be reachable to supply a valid lease.


APIPA
169.254.0.0/16 is associated with Automatic Private IP Addressing. A 169.254.x.x address on a PC expecting DHCP is a strong clue that it did not receive a normal DHCP lease.
APIPA hosts can communicate with compatible hosts on the same link, but this does not provide normal routed LAN access. The address does not identify the exact physical cause. Restore DHCP connectivity and obtain valid settings.


DNS
DNS resolves a hostname to an IP address. IP connectivity and hostname resolution are different tests.
If a PC can reach a service by IP but cannot reach the same service by hostname, DNS becomes a strong suspect. Compare its DNS configuration with the working PC and use the correct resolver.

Follow the evidence
  1. Inspect both PCs. Check whether their addresses are unique and belong to the LAN.
  2. Compare masks, gateways, DNS settings, and DHCP state.
  3. Can the affected PC ping the gateway? Can the other PC? Can it reach the service by IP and by hostname?
  4. Apply a supported correction and repeat the tests.
Do not reject a diagnosis merely because it seems simple. Two systems using the same IP address are a legitimate problem. A working comparison PC is useful, but a duplicate address can affect both PCs.
