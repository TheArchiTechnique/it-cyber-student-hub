RAID

RAID combines multiple drives into one storage array. The RAID level determines how data is stored, how much space you can use, and whether the array can keep working after a drive fails.

N = number of drives. S = capacity of one drive. These calculations use equal-sized drives, two-drive mirrors, and no spare drives. Formatting and controller overhead reduce the final usable space.

How RAID stores data

Striping: splits data across drives so multiple drives can work at the same time.

Mirroring: keeps a copy of the same data on another drive.

Distributed parity: spreads recovery information across the drives. The controller uses that information and the remaining data to rebuild a failed drive.

Replacing a drive

Start by matching the original drive’s specifications. If an exact replacement is unavailable, use these rules.

Protocol: SAS or SATA

A protocol defines how the drive and controller communicate. SAS and SATA use different commands and features.

Replace SAS with SAS and SATA with SATA. Most hardware RAID controllers require one protocol per array, even when the controller supports both types in separate arrays.

Drive type: HDD or SSD

An HDD stores data on spinning magnetic platters. An SSD stores data in flash memory and has no moving parts.

Replace an HDD with an HDD and an SSD with an SSD. Most hardware RAID controllers do not allow the two types in the same array.

Capacity: same size or larger

The replacement needs enough space for all the data assigned to that member. A drive that is too small cannot be used for the rebuild.

A larger drive can work, but its extra space does not automatically increase the array’s capacity. For example, replacing a 2 TB member with a 4 TB drive still gives that member 2 TB of usable space in the existing array.

Speed: same or faster

For HDDs, match the RPM or choose a faster drive. A slower replacement can slow down the entire array because operations may have to wait for that drive.

Also match or exceed the interface link rate. Gb/s describes the connection speed, not the speed of every file transfer. One faster replacement does not make the other drives faster.

Brand

Use the same model when available. A different brand can work if the specifications match and the server and RAID controller support it.

The brand name alone does not make a drive compatible.

Physical size and support

Match the drive’s form factor, such as 2.5-inch or 3.5-inch, and use the correct carrier.

Check the server’s supported-drive list for an approved replacement. Firmware and sector format also affect compatibility. Two drives labeled with the same capacity can have slightly different usable sizes.

Failed vs. predicted failure

Failed: the drive is offline and no longer contributing data to the array.

Predicted failure: the drive still works, but its health monitoring has reported a problem. Plan to replace it before it fails.

Degraded: the array has lost some redundancy. It may still work, but it has less protection against another failure.

Allow the rebuild to finish

A rebuild restores the missing drive’s data onto its replacement. Installing the new drive does not finish the job.

For example, if a RAID 5 array has one failed drive and another with a predicted failure, replace the failed drive and finish its rebuild first. Removing the other drive before that would leave two drives missing.

Verify backups before service and confirm the array is healthy after rebuilding. RAID protects against certain drive failures; backups protect your data from problems such as deletion and ransomware.
