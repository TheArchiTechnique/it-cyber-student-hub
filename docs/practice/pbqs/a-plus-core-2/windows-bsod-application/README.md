# Windows BSOD and Application Troubleshooting

Investigate three Windows workstations through interactive stop screens, recovery menus, desktop tools, error dialogs, and a simulated administrator Command Prompt.

- [Launch Windows BSOD and Application Troubleshooting](https://thearchitechnique.github.io/it-cyber-student-hub/practice/pbqs/a-plus-core-2/windows-bsod-application/app/)

Use Safe Mode, Device Manager, Event Viewer, Reliability Monitor, Windows Memory Diagnostic, Installed Apps, and approved software packages. Perform driver rollback, isolate and replace a defective memory module on the powered-off service bench, and recover an application with a missing runtime and interrupted update. The memory fault varies between the original modules, so use diagnostic findings before replacing parts.

Submit for up to 18 points with targeted feedback. Correct repairs receive credit independently from diagnostic evidence. Verify normal startup and the original workload; for the application, verify launch and export. Retry troubleshooting retains the current investigation and repair state. Reset attempt restores all original faults and retains the same defective module for repeat practice.

The Lesson tab explains stop-code interpretation, driver and memory isolation, logs, application crashes and dependencies, SFC/DISM, and repair verification. It links to the [Windows Command-Line Reference](../../../../reference/windows-command-line.md). Commands and hardware actions affect only this simulation. Progress and optional service notes are saved in this browser when storage is available.
