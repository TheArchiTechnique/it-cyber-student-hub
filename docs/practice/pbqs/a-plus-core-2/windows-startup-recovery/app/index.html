Service notes

Recover the boot path

Identify where startup stops. Confirm the disk and firmware configuration, inspect the recovery evidence, then repair the component that failed.

1 · From power-on to Windows

Firmware runs POST, detects storage, and selects a boot target. Windows Boot Manager reads Boot Configuration Data (BCD) and starts the Windows loader. The loader brings in the kernel and boot drivers; Windows then initializes services and the sign-in environment.

A missing-OS message appears before the desktop. It does not prove the drive is empty. A Recovery screen naming BCD means the boot path progressed far enough to report a boot configuration problem. Read the file path and error code together.

2 · Two different boot environments

BIOS / MBRUEFI / GPT
Firmware starts master boot code on disk.Firmware selects an EFI application, normally Windows Boot Manager.
The active system partition's boot sector leads to bootmgr and BCD.A FAT32 EFI System Partition stores EFI boot files and BCD.
Windows loader: winload.exeWindows loader: winload.efi

Inspect storage detection, boot order, and installed mode before changing them. Switching modes does not convert the disk or repair missing files. A GPT disk has an asterisk in DiskPart's GPT column.

3 · Interpret startup symptoms

Operating System not found can reflect an incorrect boot target, firmware-mode mismatch, or missing boot components. Check whether the intended disk is detected and selected.

Error loading operating system on a legacy system can indicate trouble reading or executing the next boot stage. Confirm the disk, partition layout, and boot records before choosing a repair.

Recovery code 0xc000000f accompanied by \EFI\Microsoft\Boot\BCD or \Boot\BCD directs attention to boot configuration. A code alone is not a complete diagnosis. CHKDSK reporting a healthy file system does not prove that boot files are present or correct.

4 · Navigate Windows RE

From Choose an option → Troubleshoot → Advanced options, select the tool suited to the evidence. If local recovery cannot load, boot compatible recovery or installation media and choose the repair path.

Startup Repair attempts automatic repairs. If it fails, inspect its report and Windows\System32\LogFiles\Srt\SrtTrail.txt. Failure does not prove Windows must be reinstalled.

Command Prompt supports manual investigation. Startup Settings changes how Windows starts; Safe Mode still needs a working boot path. System Restore needs a usable restore point. Uninstall Updates is appropriate when evidence connects the issue to an update. Available options depend on the device and recovery environment.

5 · Four BOOTREC operations

CommandPurpose
bootrec /fixmbrWrites master boot code without replacing the partition table. Does not rebuild BCD.
bootrec /fixbootWrites a new partition boot sector. Does not recreate the EFI boot environment.
bootrec /scanosFinds compatible installations not already represented in the BCD store. Makes no repair.
bootrec /rebuildbcdScans and asks which detected installations to add to the boot list.

Read prompts and results. Answering N does not add the installation. Zero identified installations can mean Windows is already listed. Access denied or a missing system device means the requested operation did not complete. A successful MBR write does not establish that a UEFI system can boot.

6 · Identify volumes before writing

WinRE often runs from X:, a RAM disk. Installed Windows may have another letter. Use DiskPart to inspect disk and volume information, then use DIR to verify the actual Windows directory. The OS partition and system partition have different roles.

diskpart
list disk
list volume
select volume 2
detail volume
assign letter=S
exit
dir F:\Windows

This is a separate example: volume 2 is a confirmed EFI System Partition and F: contains Windows. Read the activity's own results rather than copying these values. Assign a free temporary letter only to the identified target. Formatting is not required for the repairs practiced here.

7 · BCDBoot and modern recovery

BCDBoot copies boot files from an installed Windows directory and can create a BCD store on the system partition. For a confirmed F: Windows installation and an EFI partition mounted at S:, an explicit UEFI example is:

bcdboot F:\Windows /s S: /f UEFI

/f BIOS selects BIOS boot files; /f ALL copies both sets. These options do not convert disk layouts. Wrong source or destination letters can fail or write to the wrong volume. Copying files for an incompatible firmware type can report success while leaving the installed boot path unrepaired.

On UEFI, BCDBoot without /s normally uses the firmware-identified system partition and can update the Windows Boot Manager firmware entry. With /s, it copies to the specified partition and does not create that NVRAM entry. This activity's Computer A retains its firmware entry, so repairing its existing EFI partition is sufficient.

For offline BCD inspection, specify the store explicitly, such as bcdedit /store S:\EFI\Microsoft\Boot\BCD /enum. The default store from recovery USB may describe the recovery media instead of installed Windows.

8 · Verify the original problem is resolved

After repair, restart using the internal drive and correct firmware mode. Confirm a normal Windows boot and desktop, then document your findings. A command's success message reports that operation, not the health of the whole boot chain.

In this activity, Startup Repair reports are deterministic, repairs finish immediately, and there is no BitLocker prompt. Each computer preserves its own firmware settings, terminal history, and repair state. Unsupported commands do not run on your computer.
