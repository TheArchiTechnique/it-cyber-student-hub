    Troubleshoot with evidence

    A command answers a specific question. Read its result, compare it with the expected configuration, and choose the next useful test.

    1 · Commands, switches, and parameters

    In ping -n 2 192.168.18.1, ping is the command, -n is a switch, 2 is its value, and the address is the target parameter. Windows commands can use different switch conventions.

    hostname
TRAINING-PC07

whoami
training\llee

    The computer name identifies the device; the account identifies the security context. These are different facts. help lists this activity's supported commands; ipconfig /? shows syntax. On real Windows, HELP covers CMD commands; many utilities provide their own /?.

    See the reference's command help examples.

    2 · DHCP and APIPA

    ipconfig shows adapter addressing. /all adds DHCP status, DNS servers, and other configuration. Read the active adapter.

    Autoconfiguration IPv4 Address : 169.254.25.64
Subnet Mask                   : 255.255.0.0
Default Gateway               :

    This is link-local addressing. With DHCP enabled, it commonly means no usable lease was obtained. It does not identify whether the DHCP service, relay, VLAN, or path failed. ipconfig /renew requests a lease; it cannot repair an unreachable DHCP service.

    Review IP configuration and renewal.

    3 · IP reachability and DNS

    Compare a numeric test with a hostname test, then query DNS directly.

    ping 192.168.18.30
Reply from 192.168.18.30: bytes=32 time<1ms TTL=128

nslookup files.training.example
DNS request timed out.

    A working numeric ping plus failed name resolution points toward DNS investigation. Check which resolver the client uses. nslookup name resolver-IP can compare resolvers. A ping reply proves ICMP reachability, not SMB or web-service availability; timeouts can reflect filtering.

    Review DNS lookup results. Clearing the client cache does not correct a wrong resolver address.

    4 · Mapped shares and accounts

    net use lists connections visible to the current account. A drive letter points to a UNC path: \\server\share. Compare that path with the approved resource, and use whoami and hostname to confirm context.

    Status  Local  Remote
OK      M:     \\training-fs\classwork

    A reachable file server can still host an unavailable share. A correct mapping can still fail because of permissions or credentials. Match the evidence before changing access. Removing a mapping disconnects that connection; it does not delete the shared files.

    For syntax, read network-share connections. Use the signed-in user's context for drive mappings; an elevated console can have different mappings.

    5 · View policy versus refresh policy

    gpresult /r reports resulting policy. gpresult /scope user /r limits the report to the user. Computer-scope reporting can require elevation.

    USER SETTINGS
Last time Group Policy was applied: Today at 09:10
Applied Group Policy Objects
    Training-Desktop

    Compare the report's scope, application time, source controller, and GPO list with the approved deployment. gpupdate /force reapplies settings. /target:user or /target:computer limits processing.

    A refresh cannot correct an inapplicable security filter or broken domain connectivity. Some extensions require sign-out or restart. Verify the intended GPO after processing; a success message alone does not prove it applied.

    Review policy reporting and policy refresh behavior.

    6 · Protected system files

    sfc /verifyonly checks protected Windows files without repairs. sfc /scannow checks and attempts repairs. Both require an authorized elevated console.

    Windows Resource Protection found corrupt files
and successfully repaired them.

    Distinguish no violations, successful repair, and corruption that could not be repaired. SFC does not validate every application or personal file. If repair fails, review CBS logs and investigate the repair source; Windows servicing with DISM may be needed. Verify the original symptom after repair.

    Review System File Checker results.

    7 · File-system integrity and restart

    chkdsk C: inspects volume structures. It needs elevation here and does not request repair. Checks of an active volume can report transient inconsistencies; protect data and confirm the findings. /f requests logical-error repair.

    Cannot lock current drive.
Would you like to schedule this volume to be checked
the next time the system restarts? (Y/N)

    Accepting this prompt schedules work. It does not complete the repair. Coordinate the restart, review the boot-time check in the Application log under Wininit, and verify afterward. Logical corruption does not by itself prove hardware failure. CHKDSK does not replace SFC's protected-file checks.

    Read volume checking and repair options.

    8 · Apply a troubleshooting method

    1. Identify the issue and expected behavior.
    2. Establish possible causes from symptoms and context.
    3. Test the likely cause with relevant commands.
    4. Plan the change, including permissions, backup, and downtime.
    5. Implement the approved solution and verify functionality.

    A valid address does not prove DNS works. A successful policy refresh does not prove a specific setting applied. A scheduled check does not prove repair occurred. Compare the final results with the original problem and document what changed.
