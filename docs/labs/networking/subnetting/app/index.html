From an address to a complete subnet

A subnet is a block of IPv4 addresses that share the same network bits. A mask tells you which bits belong to that shared network and which can identify hosts inside it. We will build that mask, find the block's first and last addresses, and calculate its capacity.

Start with binary, then follow the eight steps. Open the workspace whenever you want to practice. Switching sections keeps your entries.

1. Understand IPv4 and binary place values

An IPv4 address has 32 bits, split into four octets of eight bits. In decimal, the octets are separated by dots, as in 192.168.10.130. Each octet ranges from 0 to 255. A bit can be only 0 or 1.

Binary uses place values, just as decimal does. From left to right, the eight places are:

1286432168421

A 1 includes that place value in the sum; a 0 leaves it out. With all eight bits set, 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255. With all bits clear, the value is zero.

Decimal to binary: 13

Starting on the left, ask whether each place value fits in the amount remaining. 128, 64, 32, and 16 are too large, so write four zeros. Include 8, leaving 5; include 4, leaving 1; skip 2; include 1. Keep the leading zeros to show all eight positions.

Value   128  64  32  16   8   4   2   1
Bit       0   0   0   0   1   1   0   1
Sum                       8 + 4     + 1 = 13
Binary: 00001101

Binary to decimal: 10100010

Read the 1 positions: 128 + 32 + 2 = 162. The zero positions add nothing. Each octet is a separate eight-bit value; do not join the decimal octets into one decimal number.

Network bits identify the subnet; host bits identify positions inside it. A subnet mask marks network positions with 1 and host positions with 0. CIDR (Classless Inter-Domain Routing) writes the number of network bits after a slash. In /26, 26 of the 32 positions are network bits, leaving 6 host bits. The slash is not a division operation.

Try before moving on: write 25 as eight bits

Include 16, 8, and 1: 00011001. Convert back by adding 16 + 8 + 1 = 25.

2. Convert CIDR to a subnet mask

  1. Draw 32 positions, grouped into four octets.
  2. Fill the first N positions with 1, where N is the prefix.
  3. Fill all remaining positions with 0.
  4. Convert each eight-bit octet to decimal using its place values.

For /26, the first three octets use 24 network bits. Put two more 1s in the last octet, then six 0s. Those two 1s are worth 128 + 64 = 192.

Mask bits   11111111.11111111.11111111.11000000
Decimal          255.     255.     255.     192
Positions   <----- 26 network bits -----><6 host>

A mask always has consecutive 1s followed by consecutive 0s. A value such as 255.0.255.0 is not a valid contiguous subnet mask.

Changing the prefix changes which positions are network positions. Every added network bit removes one host bit, halving the number of possible host-bit combinations.

3. Convert the IP address to binary

Convert each octet independently. For 192.168.10.130: 192 is 128 + 64; 168 is 128 + 32 + 8; 10 is 8 + 2; and 130 is 128 + 2. Write eight digits for every octet and line the address up above the mask.

IP decimal       192.     168.      10.     130
IP binary   11000000.10101000.00001010.10000010
Mask        11111111.11111111.11111111.11000000

The same address belongs to different-sized blocks when you change the mask. The IP address alone does not tell you where its subnet begins.

4. AND matching bits to find the Network ID

AND is a logical operation: its result is 1 only when both input bits are 1. It is not binary addition and has no carry.

000

A mask bit of 1 keeps the address bit. A mask bit of 0 clears it. AND therefore keeps the network portion and sets every host position to 0, producing the network address, also called the Network ID.

Inspect the last octet below. The outlined column pairs the same bit position in all three rows. The first two positions are network bits; the other six are host bits.

Position12345678 RoleNNHHHHHH IP (130)10000010 Mask (192)11000000 AND (128)10000000 
IP          11000000.10101000.00001010.10000010
Mask        11111111.11111111.11111111.11000000
AND result  11000000.10101000.00001010.10000000
Network ID       192.     168.      10.     128

Convert the result back one octet at a time. In the final octet, only the 128 position is 1, so the Network ID is 192.168.10.128.

5. Find the broadcast address using the wildcard

In a conventional subnet, the broadcast address is its last address. It keeps the same network bits and sets every host bit to 1.

  1. Start with the mask. Its 0 positions identify host bits.
  2. Invert every mask bit to form the wildcard mask: network positions become 0; host positions become 1. For /26, the wildcard is 0.0.0.63.
  3. Use OR between the Network ID and wildcard. OR produces 1 if either input is 1: 0 OR 0 = 0, 0 OR 1 = 1, 1 OR 0 = 1, 1 OR 1 = 1.
  4. Convert all four result octets back to decimal.
Mask        11111111.11111111.11111111.11000000
Wildcard    00000000.00000000.00000000.00111111

Network ID  11000000.10101000.00001010.10000000
Wildcard    00000000.00000000.00000000.00111111
OR result   11000000.10101000.00001010.10111111
Broadcast        192.     168.      10.     191

The last six bits changed from 000000 to 111111; the network bits stayed the same. The final octet is 128 + 32 + 16 + 8 + 4 + 2 + 1 = 191.

Network ID + Wildcard Mask = Broadcast Address

Here, 192.168.10.128 + 0.0.0.63 = 192.168.10.191. Addition gives the same result as OR because the Network ID has 0s everywhere the wildcard has 1s, so no bit produces a carry. Treat these as complete 32-bit address values, not four unrelated decimal sums.

For /31 and /32, the same operation finds the block's upper boundary, but it is not a directed broadcast address. See the next step.

6. Determine the first and last usable host

For a conventional IPv4 subnet with at least two usable host addresses, the first address identifies the network and the last addresses all hosts in that subnet. These two addresses are reserved for those purposes and are not assigned to ordinary hosts.

  • First usable = Network ID + 1. Here, 192.168.10.129.
  • Last usable = broadcast − 1. Here, 192.168.10.190.

The conventional subnet runs from 192.168.10.128 through 192.168.10.191, while its usable range runs from 192.168.10.129 through 192.168.10.190. Do not remove an address just because its last octet is 0 or 255; the complete address and mask determine its role.

Advanced exceptions: /31 and /32

A /31 on a point-to-point link uses both addresses as endpoints, with no reserved Network ID or directed broadcast address. For 192.0.2.10/31, the lower boundary is .10 and the upper is .11; both are endpoints. This requires point-to-point use and supporting devices (RFC 3021).

A /32 identifies one address, commonly a host route or loopback address. It has no host bits and no directed broadcast. For 192.0.2.10/32, the lower and upper boundaries are both 192.0.2.10. In this lab, record that single address for both usable-range fields and a capacity of 1. These entries describe the address block, not an ordinary multi-host LAN.

For either exception, enter N/A in the decimal broadcast field. The binary upper-boundary row still follows Network ID OR wildcard. The subtraction-of-two rule does not apply.

7. Calculate host capacity

Each host bit has two possible values. With h host bits, there are 2h combinations, including the all-zero and all-one patterns.

  • Host bits = 32 − prefix
  • Total addresses = 2host bits
  • Conventional usable hosts = total addresses − 2
PrefixHost bitsTotal addressesUsable hosts
/2432 − 24 = 828 = 256254
/2332 − 23 = 929 = 512510
/2532 − 25 = 727 = 128126

Keep total addresses separate from usable hosts. A requirement for 128 ordinary hosts does not fit a /25, which has only 126 usable addresses. A /24 is the smallest conventional subnet that fits that requirement. /31 point-to-point links have 2 endpoints; /32 blocks identify 1 address.

Example B: 172.16.5.200/23 crosses an octet boundary

23 network bits leave 9 host bits: one in the third octet and all eight in the fourth. The third mask octet is 11111110 (254), so the wildcard is 0.0.1.255.

IP          10101100.00010000.00000101.11001000
Mask        11111111.11111111.11111110.00000000
AND         10101100.00010000.00000100.00000000
Wildcard    00000000.00000000.00000001.11111111
AND OR wild 10101100.00010000.00000101.11111111

AND changes the third octet from 5 to 4 and clears the fourth octet, giving 172.16.4.0. Setting all nine host bits produces 172.16.5.255. The usable range is 172.16.4.1 through 172.16.5.254; there are 29 = 512 total addresses and 510 usable hosts. Both 172.16.4.255 and 172.16.5.0 are usable addresses inside this block.

The subnet mask is 255.255.254.0. Adding the wildcard to the network gives the same upper boundary: 172.16.4.0 + 0.0.1.255 = 172.16.5.255. The next /23 begins at 172.16.6.0, not 172.16.5.0.

Use different subnet sizes with VLSM

Variable Length Subnet Mask (VLSM) uses different prefix lengths within a larger address block. Choose each subnet's size to fit its host requirement, rather than giving every group the same-sized subnet.

Within 192.168.40.0/24, allocate largest requirements first. For 50 hosts, 5 host bits give only 30 usable addresses; 6 give 62, so choose /26. Then allocate smaller blocks on valid boundaries without overlap:

Needed hostsSubnetComplete blockUsable capacity
50192.168.40.0/26.0 through .6362
20192.168.40.64/27.64 through .9530
10192.168.40.96/28.96 through .11114

The remaining addresses, .112 through .255, are still unallocated. VLSM does not change the AND, OR, or capacity calculations; you apply the same process to each chosen prefix.

    Double and halve from /24

    /22: 1024 ← /23: 512 ← /24: 256 → /25: 128 → /26: 64

    A prefix one bit shorter doubles total addresses. One bit longer halves them. During a timed question, start at the known /24 value and count the steps, then subtract two for conventional usable hosts. For /27: 256 → 128 → 64 → 32 total, giving 30 usable.

    Place values and mask octets

    128 · 64 · 32 · 16 · 8 · 4 · 2 · 1

    Valid partial mask octets: 128, 192, 224, 240, 248, 252, 254. A fully network octet is 255; a fully host octet is 0. These values come from adding consecutive place values from the left.

    Find boundaries with a block size

    1. Find the interesting octet: the first mask octet below 255. A partial octet contains the network/host boundary; for an octet-aligned prefix such as /24, use the following all-host octet (0).
    2. Block size = 256 − that mask octet. /26 gives 256 − 192 = 64. /23 gives 256 − 254 = 2 in the third octet.
    3. Round the IP's interesting octet down to a block multiple. Keep earlier network octets and set later octets to 0. For .130/26, multiples are 0, 64, 128, 192; choose 128.
    4. Next subnet: add one block in that octet, carrying to the previous octet if needed. For 192.168.10.128/26, next is 192.168.10.192. For 172.16.4.0/23, next is 172.16.6.0.
    5. Broadcast: take the full address immediately before the next subnet. That gives 192.168.10.191 or 172.16.5.255. If the block ends at 255.255.255.255 there is no next IPv4 subnet; use Network OR wildcard.

    /32 has no host octet and identifies one address. /0 covers the whole IPv4 space. The block method finds numeric boundaries; special-purpose ranges can restrict how addresses are actually used.

    Choose a size and finish the range

    • Needed ordinary hosts: choose the smallest h for which 2h − 2 meets the requirement, then prefix = 32 − h. 50 hosts need h = 6, giving /26 and 62 usable hosts.
    • Network: IP AND mask. Wildcard: invert the mask. Broadcast: Network OR wildcard.
    • Usable range: network + 1 through broadcast − 1 for conventional subnets. A /23 has 512 total addresses and 510 usable hosts, not 512 usable hosts.
